# Draw the Owl -> Familiar

`Familiar` is an evolution of Draw the Owl, not a thematic rewrite.

Source project: https://github.com/bdf1992/Owl

## What remains load-bearing

Draw the Owl already reduced its ordinary reasoning surface to four handles:

- **Target** — the result being sought.
- **Current** — the latest accepted or inspectable result.
- **Mark** — feedback, evidence, constraint, or reason to change Current.
- **Pass** — a complete new attempt at the authorized scope.

It also established several mature disciplines that Familiar should inherit as **Owl expertise**:

- finish a recognizable Whole instead of substituting preparation or fragments;
- preserve an adopted instance across ambiguous corrections;
- distinguish Target identity from the Commission governing style/method/presentation;
- make unknowns smaller through cheap consequential probes;
- use Shapes -> Parts -> Features -> Whole as a flexible drawing rhythm rather than a state machine;
- externalize deterministic bookkeeping and long-horizon continuity;
- ground substantial work in an authorized Nest/environment;
- retain evidence and consequential residuals;
- use metaphor as attention guidance, never as a requirement that reality obey the metaphor;
- audit new rules against Human, Shared, Model, Actual, and Meta fidelity.

## What changes

### Before

```text
Draw the Owl skill
  -> helps draw a Target
  -> Owl is the canonical completion metaphor
  -> OWL_ENGINE carries durable/runtime state
```

### After

```text
Spell Protocol / Runtime
        |
        v
Familiar Spell
        |
        v
       Owl
system Familiar + Familiar-maker
        |
        v
caster's Familiar
        |
        v
later Spell casts
```

The Owl becomes the canonical Familiar of Familiar itself.

Its special competence comes from the history above: it knows how to turn an ambiguous mark into a recognizable complete form, preserve identity through revision, and identify Halfhorse-style substitutions where preparation is masquerading as completion.

## Owl is not the Spell protocol

Do not lift every Draw-the-Owl concept into universal Spell vocabulary.

These belong to the Familiar/Owl implementation unless another independent Spell proves them universal:

- Shapes / Parts / Features / Whole
- drawing / ink / sketch / color
- owl imagery
- eggs and hatching
- Familiar form
- strengths and shadows
- Patronus-style summoning quiz
- pattern-commons guidance for identity formation

The Spell protocol stays smaller: inherent ability, invocation/expressions, telemetry, requirements, limits, energy, effects, evidence, Trials, standing, and receipts.

## Egg migration

OWL_ENGINE eggs were bounded continuations derived from Current + Mark. They remain useful, but should become an explicit long-horizon continuation mechanism rather than a universal Spell requirement.

A future runtime continuation can preserve the semantics:

```text
parent effect/current
+ unresolved Mark
+ expected bounded continuation
+ custody
+ evidence
-> continuation handle
```

Familiar/Owl may continue to call such a continuation an **egg**. Other Spells may use different magic language or no metaphor at all.

## Commission migration

Commission remains a strong Familiar concept because a Familiar carries user expression, style, preferences, and method without redefining the thing being acted on.

Spell itself does not require the word Commission. The generic protocol has caster input, Familiar participation, requirements, limits, and energy. A Spell implementation may define richer preference contracts when needed.

## The Owl's new job

Owl helps a holder make a well-formed Familiar.

It should be good at noticing:

- form without systemic pull;
- metaphor with no operational meaning;
- strengths without their shadows;
- unlimited or unjustified stake;
- identity pronouncements not recognized by the holder;
- autonomous form drift;
- decorative jargon that does not improve casting;
- a candidate that describes the holder poorly despite sounding clever;
- a Familiar so rigid that it overrides reality;
- a Familiar so vague that it cannot influence later casting.

The Owl may suggest. The holder recognizes/adopts.

## Compatibility path

Draw the Owl can remain installable for existing Skill hosts while delegating new Spell-native behavior to Familiar when a Spell runtime exists.

Possible later compatibility wrapper:

```text
compatibility/draw-the-owl/SKILL.md
```

The wrapper should:

1. preserve the original trigger language and completion discipline;
2. detect/use a Spell runtime only when actually available;
3. route `summon familiar` / `summon owl` to the Familiar Spell;
4. never claim persistence, telemetry, or registration when the runtime is unavailable;
5. continue functioning as an ordinary Draw-the-Owl Skill otherwise.

This allows migration without declaring Agent Skills obsolete.

## Version boundary

This is a semantic major change to the project even if compatibility is preserved:

> Draw the Owl taught the Owl how to finish a form.
> Familiar gives the Owl a runtime in which it can help other forms become themselves.

The first acceptance target is not feature parity with OWL_ENGINE. It is one complete native casting:

```text
new holder
-> Summon Familiar
-> Owl studies authorized evidence
-> provisional candidate
-> holder Marks/adopts
-> registered Familiar
-> later Recall
-> later cast measurably influenced by that Familiar
```

If that sequence is executable, inspectable, and bounded by telemetry/authority, Draw the Owl has successfully crossed into Familiar rather than merely being renamed.
